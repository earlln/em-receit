# EM 영수증 정리

Google Drive **내 드라이브 > EM > 미청구** 폴더에 올라온 영수증의 파일명을
정해진 규칙으로 바꾼다. 필요한 도구는 Google Drive 커넥터(`mcp__Google_Drive__*`)다.
도구가 로드되지 않았으면 ToolSearch로
`select:mcp__Google_Drive__search_files,mcp__Google_Drive__download_file_content,mcp__Google_Drive__update_file`
을 먼저 로드한다.

## 기본 실행 (`em-receit`만 입력했을 때)

사용자가 `em-receit` 또는 `/em-receit`만 입력하거나 "정리해줘"처럼 범위를 정하지 않고 요청하면,
묻지 말고 아래를 한 번에 끝까지 진행한다.

1. 미청구 폴더에서 이름이 아직 규칙 형식이 아닌 영수증 파일(이미지와 PDF)을 **모두** 찾는다.
   아래 "절차"의 1~4단계로 이름을 바꾼다.
   - 이미 정리된 파일과 똑같은 사진이 다시 올라왔으면(픽셀 비교로 확인) 이름을 바꾸지 않는다. 중복으로 보고한다.
   - 금액이나 날짜를 확실히 읽지 못했거나 카테고리가 애매한 파일은 건너뛴다. 나머지 파일 처리는 계속한다.
     건너뛴 파일은 마지막에 모아서 묻는다.
2. 이름 바꾸기가 끝나면 이어서 아래 "합산" 절차를 진행한다. 정리된 파일 전체를 기준으로 계산한다.
3. 보고는 아래 순서로 한 번에 한다.
   - 이번에 바꾼 파일: `기존 이름 → 새 이름`과 판단 근거 한 줄. 바꾼 파일이 없으면 "새 영수증 없음"이라고 쓴다.
   - 건너뛴 파일과 중복 파일, 각각의 이유
   - 합산 결과: 카테고리 표와 건별 내역
   - 맨 끝에 복사용 코드 블록: 이번에 바꾼 영수증의 금액을 하나씩, 그다음 전체 금액

## 파일명 규칙

```
<카테고리>_<영수금액>_<영수일자>.<원래 확장자>
예) 간식_81450_20260930.jpg, 예배기타_113050_20260918.pdf
```

- **영수금액**: 실제 결제한 최종 금액이다(합계 / 승인금액 / 카드 결제액). 쉼표와 "원"은 빼고 숫자만 쓴다.
  쿠폰 할인 전 금액이나 부가세 제외 금액은 쓰지 않는다.
- **영수일자**: 영수증에 찍힌 거래일자를 `YYYYMMDD`로 쓴다. 업로드일이나 파일 수정일은 쓰지 않는다.
  `09/30/2026`처럼 미국식으로 표기된 날짜는 월/일/연 순서로 읽는다.
- **확장자**: 원래 확장자를 그대로 유지한다.

### 카테고리

| 구매 품목 | 카테고리 |
|---|---|
| 음식, 음료, 과자, 견과 등 먹을 것 | `간식` |
| 장난감, 문구류 | `수시시상` |
| 문화상품권 | `정기시상` |
| 그 밖의 모든 것 | `예배기타` |

품목이 섞여 있으면 금액이 가장 큰 품목을 기준으로 정한다. 애매하면 사용자에게 확인한다.

## 절차

1. **미청구 폴더 찾기**
   - 폴더 ID는 `1bAakLoCed9bmnpRtqZVREgAJD9qJCrVa`다. 찾을 수 없으면 `title = '미청구'` 조건과
     폴더 mimeType으로 검색한다.
   - `parentId = '<폴더ID>'`로 파일 목록을 가져온다(`excludeContentSnippets: true`).
2. **바꿀 대상 고르기**
   - 규칙 형식(`^(간식|수시시상|정기시상|예배기타)_\d+_\d{8}\.`)이 아닌 파일만 대상이다.
     예를 들어 카카오톡 사진의 기본 이름인 `1790766182962.jpg` 같은 파일이다.
   - 사용자가 특정 파일을 지목했으면 그 파일만 처리한다.
3. **영수증 읽기**
   - **이미지**: `download_file_content`의 결과가 크면 파일로 저장된다. 그 파일을 디코딩하고 줄여서 Read로 본다.
     ```bash
     S=<scratchpad>; pip install -q pillow
     jq -r .content <저장된 결과 파일> | base64 -d > $S/r.jpg
     python3 -c "from PIL import Image,ImageOps as O; im=O.exif_transpose(Image.open('$S/r.jpg')); im.thumbnail((1600,1600)); im.save('$S/r_small.jpg',quality=85)"
     ```
     글씨가 작으면 금액이나 날짜 부분을 잘라서 확대해 다시 본다.
   - **PDF**: `read_file_content`로 텍스트를 먼저 읽는다. 읽을 수 없으면 다운로드해서 페이지를 이미지로 확인한다.
4. **이름 바꾸기**
   - `update_file`(fileId, title)로 바꾼다.
   - 같은 이름의 파일이 이미 있으면 덮어쓰지 말고 사용자에게 알린다.
5. **보고**
   - 파일마다 `기존 이름 → 새 이름`을 보고하고, 판단 근거로 구매처, 주요 품목, 금액, 일자를 한 줄씩 쓴다.
   - 금액이나 날짜를 확실히 읽지 못했으면 추측으로 바꾸지 않는다. 사용자에게 확인을 받는다.
6. **영수금액 복사용 출력**
   - 세션이 클라우드 컨테이너에서 돌기 때문에 사용자 폰의 클립보드에 직접 쓸 수 없다.
   - 대신 응답 맨 끝에 영수금액을 **숫자만** 코드 블록으로 따로 출력한다. 사용자는 코드 블록의 복사 버튼을 눌러 복사한다.
     파일이 여러 개면 파일마다 코드 블록을 하나씩 만든다.
     ````
     ```
     81450
     ```
     ````

## 합산 (카테고리별 합계와 전체 금액)

"합산", "합계", "총액" 등을 요청받으면 아래 절차로 계산한다.

1. 미청구 폴더의 파일 목록을 **전부** 가져온다.
   - 한 페이지에 5개 정도만 오므로 `nextPageToken`이 없을 때까지 반복해서 가져온다.
   - 하위 폴더나 휴지통에 있는 파일은 계산에 넣지 않는다.
2. 파일명이 규칙 형식인 파일은 파일명에서 카테고리와 금액을 읽는다. 영수증을 다시 열어 읽지 않는다.
3. 규칙 형식이 아닌 파일이 있으면 합산에서 빼고 사용자에게 알린다.
   먼저 이름을 정리할지 물어본다.
4. 금액은 직접 더하지 말고 스크립트로 계산한다(예: `python3 -c`). 암산하다 틀릴 수 있다.
5. 아래 형식으로 보고한다.
   - 카테고리 표: 카테고리, 건수, 합계. 4개 카테고리를 모두 넣고, 건이 없는 카테고리는 0원으로 쓴다.
     마지막 행은 **전체**다.
   - 카테고리별 건별 내역: 금액과 날짜(M/DD)를 금액이 큰 순서로 쓴다.
   - 전체 금액을 숫자만 코드 블록으로 따로 출력한다(복사용).
   - 사용자가 "미지급"처럼 다른 폴더 이름을 말해도 미청구 폴더를 가리키는 것으로 본다.
     따로 존재하는 폴더를 지목한 게 확실할 때만 그 폴더로 계산한다.
